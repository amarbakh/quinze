QUINZE Health REST API

Authenticated JSON endpoints across Clinic, Laboratory and Pharmacy — connect mobile apps, portals and devices.

Odoo 17JSON RESTAPI Key AuthPaginatedUnified Envelope

Overview

Authenticated JSON REST endpoints covering the whole suite — connect a mobile app, a patient booking site, a laboratory analyser, or an external insurance system to your Odoo backend.

Authentication

Requests carry an X-API-Key header. Keys are created and revoked from Settings → Technical → API Keys, and each key is bound to a user so all standard Odoo access rules and record rules still apply.

Endpoints

AreaCapabilities

Example Request

# List appointments for a given date GET /api/quinze/v1/appointments?date=2026-07-18&page=1 X-API-Key: your-key-here
// Response { "status": "ok", "data": [ { "id": 4, "name": "APT/2026/00004", "patient": { "id": 2, "name": "PAT/2026/00002" }, "doctor": "Dr. Alaa", "start": "2026-07-18 08:15:00", "state": "confirmed" } ], "meta": { "total": 5, "page": 1 } }

Errors use the same envelope with a status of error, an HTTP-aligned code and a message, so a client can branch on one shape across every endpoint.

Consistent Response Envelope

Every endpoint answers with the same structure — a status field, a data payload, and pagination metadata on list endpoints. Errors return the same envelope with an error code and message, so client-side handling stays simple across the entire API.

Requires: QUINZE Health Base (free), Clinic, Lab and Pharmacy modules.
